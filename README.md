# Web DJ · 无硬件控制台

一个**纯浏览器运行**的双唱盘 DJ 应用，不需要任何外接设备。用 Web Audio API 实时合成音频路由，把鼠标操作还原成旋钮、推子、转盘的手感。整个程序是**单个 `index.html` 文件**，零依赖，方便放进 U 盘带走。

## ⚠️ 先读这段：必须用 HTTP 服务器打开

**不要直接双击 `index.html`。**

用 `file:///` 协议打开时，浏览器会禁止 `fetch(blob:…)`，导致**所有本地音频都解码失败**（页面上会弹出黄条提示）。这是浏览器安全限制，不是 bug。

在本文件所在目录起一个本地服务器，然后访问 `http://localhost:8080/`：

```bash
python -m http.server 8080
# 或
npx serve .
```

> 首次播放会在你点击「播放」时激活 `AudioContext`（浏览器自动播放策略要求用户手势）。

## 功能一览

- **双唱盘（Deck A / B）**：播放/暂停、真实 CUE 点（短按设点、按住预览）、SYNC（BPM + 相位对齐）、调速推子、三段 EQ、通道推子、交叉推子、EJECT 卸载
- **真·搓碟**：按住 jog 轮拖动 = 黑胶手感，支持**倒放**与实时音高变化；暂停态下搓碟松手会回到暂停（CDJ 行为）
- **可视化**：转盘进度环 + 进度条 + **可交互波形**（点击/拖动跳转，波形上标出 cue 点、hot cue、loop 区间）、每路与主输出电平表
- **Loop 循环**：手动 IN / OUT，或按 BPM 建 1/2/4/8 拍循环
- **Hot Cue 热键点**：4 个，点击设点/跳转，右键清除
- **切歌辅助系统**：
  - **BPM 检测**（载入即离线全曲分析，精度 ±1）
  - **调性估算**（FFT + Krumhansl-Schmuckler 大小调模板相关，输出如 `Am` / `C`）
  - BPM 差值 / 调性兼容提示（含关系大小调）/ 节拍对齐闪点 / 一句话切歌建议
  - **TAP 打拍**手动测速
- **Auto DJ 模式**：自动起播 → BPM 同步 → 相位对齐 → 渐变 EQ → 混响过渡，并按兼容度**智能选曲**
- **混音导出**：`MediaRecorder` 录主输出为 `webm` 下载
- **播放列表持久化**：IndexedDB 保存音频文件与元数据，刷新/重启不丢
- **智能排序**：按 BPM 升序

## 架构（单文件，分层）

```
界面层 UI ── 旋钮/推子/转盘/进度环/波形（纯 DOM + CSS / canvas）
    │
控制层 ── 事件绑定 + requestAnimationFrame 时钟 tick() 统一刷新
    │
播放列表模型 ── tracks[]（文件名 / URL / 时长 / BPM / 调性 / intro/outro / fileId）
    │
音频引擎 AudioEngine
    ├─ 每路 Deck 音频图（音源为 AudioBuffer，非 <audio>）：
    │     AudioBufferSourceNode → [low shelf → mid peaking → high shelf] EQ
    │            → channelGain → crossGain → masterBus（扬声器）
    │                           └→ cueGain  → cueBus（监听）
    │                           └→ reverbSend → 全局混响 → masterBus
    ├─ Mixer：交叉推子（等功率 cos/sin）、主音量、监听音量
    └─ 导出：masterBus → MediaStreamDestination → MediaRecorder
    │
持久化 ── IndexedDB（files 存音频 Blob，playlistMeta 存元数据，防抖写入）
```

### 几个关键实现

- **播放引擎是 `AudioBuffer` + `AudioBufferSourceNode`**，不是 `<audio>` 元素。这样才能做搓碟（负 `playbackRate` = 原生倒放）。代价是 `source` 节点一次性，seek 必须重建；搓碟与波形拖动都做了复用/节流处理。
- **搓碟**不重建节点，而是把「当前位置」重设为基准后只改 `playbackRate`（见 `Deck._retime`），避免硬切爆音。
- **BPM**：离线全曲分析（RMS 包络 → onset 峰值 → 间隔直方图众数 → 众数邻域取均值消除分桶偏差 → 八度折叠）。实时检测只驱动节拍闪点，不回写离线结果。
- **调性**：16384 点 radix-2 FFT → 按真正八度取 bin（抛物线插值求峰值）→ 12 维 chroma → 与 24 个 K-S 大小调模板做皮尔逊相关。帧长 4096 时分辨率只有 10.8 Hz，相邻半音会互相污染导致 chroma 几乎是平的；16384 点（2.7 Hz）才能分开。
- **调速**：±15% 内时间伸缩听感基本无损，推子会实时显示百分比并在超出安全区时标黄。
- **混响**：`ConvolverNode` + 程序生成的指数衰减脉冲响应。
- **Auto DJ 状态机**：`idle → scanning`（监听曲末/自动起播）→ `ready`（对齐 BPM/相位、等解码）→ `transitioning`（8 秒渐变：等功率交叉 + 低音交换 + 中频缓入 + 混响 washout）→ 回到 `scanning`。

## 已知限制

- **必须 HTTP 协议**（见顶部说明）。
- **浏览器为单输出**：CUE 监听与原曲会一起从扬声器出，真正的耳机分离需要外置声卡。
- 调速超过 ±15% 时时间伸缩算法可能出现瑕疵。
- BPM / 调性为启发式估算：共用同一组和弦音的大/小调（如 C 与 Am）在纯和弦信号上天然歧义；极端曲目可能有偏差。
- 波形解码对超大文件会占用一定内存（已用单声道峰值降采样缓解）。
- IndexedDB 存的是音频文件副本，曲库很大时会占用较多浏览器配额。

## 开发 / 验证

```bash
node _check.js    # 抽出 <script> 交给 node --check 做语法检查
node _smoke.js    # 无头冒烟测试：最小 DOM 桩跑一遍脚本 + 纯算法断言
```

`_smoke.js` 会在 Node 里用桩件执行 `index.html` 的全部脚本（验证初始化不抛异常），并对纯函数做断言：FFT 峰值位置与 Parseval 能量守恒、`keyCompat` 的模 12 环绕与关系大小调、K-S 模板往返识别，以及**端到端**——合成和弦音频跑真实调性检测、合成脉冲串跑真实 BPM 检测。改算法后先跑它。

改代码时建议从 `Deck` 类（单路音频图与播放引擎）和 `autoDJUpdate()`（状态机）入手。
